# Coding Style

## Language
- TypeScript
  - strict modeを有効にすること。
  - 型定義ファイルを活用すること。

- ESLintやPrettierなどのツールを活用し、コードの一貫性を保つこと。

## General Principles
### 可読性
- コードは読みやすく、理解しやすい構造にすること。
- 命名規則に従うこと。

### 単一責任の原則
- 単一責任の原則に従うこと。

### 適切な抽象化
- 過剰な抽象化を避けつつ、必要な抽象化は適切に行うこと。

## React / Next.js
- Server Componentを基本とすること。
- Client Componentの使用条件
  - Client Componentは必要最小限で使用すること。

## Error Handling
- エラー処理方針
  - エラーは適切にキャッチし、ユーザーに影響を与えないようにすること。
  - ログを適切に記録し、デバッグや運用に役立てること。
  - ユーザーに適切なフィードバックを提供すること。
  - エラー処理は一貫性を持たせること。

## 排他制御
- 排他制御の方針
  - 共有リソースへのアクセスは適切に排他制御を行うこと。
  - デッドロックや競合状態を避けるための設計を行うこと。

## Naming
### ファイル名の命名規則
- ファイル名は一貫した命名規則に従うこと。
  
### 変数名の命名規則
- 変数名は一貫した命名規則に従うこと。

### 関数名の命名規則
- 関数名は一貫した命名規則に従うこと。

## Comments
- コメントを書く基準
  - コメントはコードの意図や背景を説明するために使用すること。
- JSDocの方針
  - 関数やクラスにはJSDocを用いて適切にドキュメントを記述すること。

## Type Safety
- anyの扱い
  - any型の使用は極力避けること。
- 型定義の方針
  - 型定義は明示的に行い、型安全性を確保すること。
