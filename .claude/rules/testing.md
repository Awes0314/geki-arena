# Testing Rules

## Testing Philosophy
- テストはコードの品質を保証するために不可欠である。
- すべての新機能や修正には対応するテストを作成すること。
- テストは自動化され、継続的に実行されること。

## Test Types
- Unit: 個々の関数やモジュールの動作を検証するテスト
- Integration: 複数のモジュールやコンポーネントが連携して正しく動作するかを検証するテスト
- E2E: アプリケーション全体のフローが期待通りに動作するかを検証するテスト

## What Must Be Tested
- 新規機能の追加時には、その機能に対応するテストを作成すること。
- バグ修正時には、修正箇所に対する回帰テストを作成すること。
- 既存の機能に影響を与える変更を行う場合は、影響範囲をカバーするテストを作成すること。

## Test Naming
- テスト名は、テストの目的や条件を明確に表すこと。
- 一貫した命名規則に従うこと。

## Test Location
- テストファイルは、テスト用ディレクトリ`__tests__`に配置すること。
- 一貫したディレクトリ構造を維持すること。

## Before Completion
- コードの変更を完了する前に、必ず以下の手順を実行すること。
- lintを実行すること。
- type checkを実行すること。
- testを実行すること。
- すべての手順が成功したことを確認すること。
