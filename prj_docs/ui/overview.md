# UI Overview

## Design Principles
- シンプルで分かりやすい情報設計を優先し、過剰な装飾を避ける。
- `prj_docs/domain`のエンティティ・状態（開催予定/開催中/終了、募集中/成立等）を、UI上でも一貫した表現・配色で区別できるようにする。
- Tailwind CSSによるユーティリティベースのスタイリングを基本とし、Framer Motionはクリア演出・画面遷移等、効果的な箇所に限定して使用する（過剰なアニメーションを避ける）。

## Responsive Design
- オンゲキNET自体がモバイル向けサイト（`ongeki-mobile`）であり、ブックマークレットの実行もモバイルブラウザが主な利用環境と想定されるため、モバイルファーストで設計する。
- ブレークポイントはTailwind CSSの標準値（sm/md/lg/xl）を基本とする。

## Navigation
- グローバルナビゲーション: ホーム、大会、1v1、コース、通知、プロフィール/設定へ主要導線を設ける。
- モバイルではハンバーガーメニューまたはボトムナビゲーションを採用する（具体的な採用形式は実装時に確定）。
- 運営（admin）向けナビゲーションは、`role=admin`のユーザーにのみ表示する。

## Common UI
- ユーザー表示（アイコン、表示名、コースバッジ）は、ランキング・参加者一覧等、ユーザーが言及される全ての箇所で共通コンポーネントとして統一する（`components.md`の「Rating Badge」「Course Badge」参照）。
- 大会・1v1の状態（開催予定/開催中/終了、募集中/成立等）は、共通のステータスバッジコンポーネントで表現する。

## Accessibility
- WCAG 2.1 レベルAAを目標水準とする。
- 色だけに依存しない情報伝達（状態バッジにはアイコン・テキストを併記する）を行う。
- フォーム入力には適切なラベル・エラーメッセージを関連付ける。

## Mobile Considerations
- ブックマークレットの実行手順（オンゲキNET上での操作）は、モバイルブラウザでの操作を前提とした分かりやすい説明を提供する（`pages.md`の該当ページ参照）。
- タップ操作を前提としたUIサイズ（タップターゲット44px以上を目安）とする。
