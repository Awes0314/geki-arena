# UI Overview

## Design Principles
- シンプルで分かりやすい情報設計を優先し、過剰な装飾を避ける。
- `prj_docs/domain`のエンティティ・状態（開催予定/開催中/終了、募集中/成立等）を、UI上でも一貫した表現・配色で区別できるようにする。
- Tailwind CSSによるユーティリティベースのスタイリングを基本とし、Framer Motionはクリア演出・画面遷移等、効果的な箇所に限定して使用する（過剰なアニメーションを避ける）。

## Responsive Design
- オンゲキNET自体がモバイル向けサイト（`ongeki-mobile`）であり、ブックマークレットの実行もモバイルブラウザが主な利用環境と想定されるため、モバイルファーストで設計する。
- ブレークポイントはTailwind CSSの標準値（sm/md/lg/xl）を基本とする。

## Navigation
- グローバルナビゲーション: ホーム、大会、1v1、コース、通知、プロフィール/設定へ主要導線を設ける。
- モバイルではハンバーガーメニューまたはボトムナビゲーションを採用する（具体的な採用形式は実装時に確定）。
- 運営（admin）向けナビゲーションは、`role=admin`のユーザーにのみ表示する。

## Theme Colors
### モードイメージカラー
- オンゲキのボタン配置（左から赤・緑・青）に倒い、「大会＝赤」「1v1＝緑」「コース＝青」をイメージカラーとする。
- 将来的にはヘッダーをこの3要素のボタン風デザインにする構想がある（現時点では実装しない）。
- 彩度の高い色を多用せず、差し色程度の控えめな使用に留める。
- 同じ機能の要素がページによって色が異なることを避ける（ボタンの色は機能で統一し、モードカラーで変えない）。
- 適用範囲（現時点）: 大会関連ページでは、ナビゲーションの「大会」項目・ページ見出しなど控えめな箇所のみ赤を差し色として用いる。ボタンの色は全ページ共通の現状のものを維持する。1v1・コースの実装時に、同様の方針で緑・青を適用する。
- 大会の状態バッジは、1v1（緑）・コース（青）と混同しないよう、緑・青系の色を用いず、赤系・中立（グレー）で表現する。

### ネオン風の差し色
- 基調色は現状のままとする。
- サービスアイデンティティとして、faviconを踏襲した「左から水色→ピンクのグラデーション」をネオン風（わずかにぼかし・発光させる）の差し色として用いる。背景が暗い方が映える。
- 使用箱所はロゴ・ヘッダー下線・ページ見出しの下線等のごく一部に限定し、使いすぎない（見づらくなるため）。

## Common UI
- 全ページには汎用的な名称の見出し（例: 「大会」「大会の詳細」「主催中大会の管理」）を必ず表示する。個別の名称（大会名等）は見出しとは別に本文で表示する。
- 「ひとつ前の画面」があるページは、見出し右上に「○○へ」形式の戻りボタンを設ける（例: 「大会詳細へ」）。大会一覧などフロー上前の画面がないページには設けない。
- ユーザー表示（アイコン、ユーザー名、Rating区分バッジ、（あれば）コースバッジ）は、一覧・詳細・ランキング等、ユーザーが言及される全ての箇所で共通コンポーネントとして統一する（`components.md`の「User Display」参照）。
- 楽曲表示（譜面）は、一覧・詳細・作成ページ等、譜面が言及される全ての箇所で共通コンポーネントとして統一する（`components.md`の「Chart Display」参照）。
- 大会・1v1の状態（開催予定/開催中/終了、募集中/成立等）は、共通のステータスバッジコンポーネントで表現する。

## Accessibility
- WCAG 2.1 レベルAAを目標水準とする。
- 色だけに依存しない情報伝達（状態バッジにはアイコン・テキストを併記する）を行う。
- フォーム入力には適切なラベル・エラーメッセージを関連付ける。

## Mobile Considerations
- ブックマークレットの実行手順（オンゲキNET上での操作）は、モバイルブラウザでの操作を前提とした分かりやすい説明を提供する（`pages.md`の該当ページ参照）。
- タップ操作を前提としたUIサイズ（タップターゲット44px以上を目安）とする。
